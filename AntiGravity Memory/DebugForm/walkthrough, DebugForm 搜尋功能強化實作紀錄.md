# DebugForm 搜尋功能強化實作紀錄

我們成功的為除錯視窗 (`DebugForm`) 導入了更強大的搜尋與高亮機制。以下是本次更動的重點摘要：

## 1. 介面與排版調整
- 在搜尋框 (`txtDebug`) 右側新增了一個 **AND/OR 切換按鈕** (`chkSearchLogic`)。 
- 此按鈕平時顯示目前生效的邏輯 (預設為 `AND`)，點擊後會立即切換邏輯並重新整理搜尋結果。
- 使用 `Panel` 容器優化了底部搜尋區域的佈局。

## 2. 智慧型關鍵字解析
- 使用正規表示式支援**空白分隔多個單字**搜尋。
- 支援**雙引號 `""` 包裹片語**。例如輸入 `"OOM 失敗" 開始` 會被解析為：
  1. `OOM 失敗` (片語)
  2. `開始` (單字)

## 3. AND/OR 邏輯判定
- **AND 模式 (預設)**：只有當該行 (ListViewItem) 的所有子項目文字加總起來，同時包含所有解析出來的關鍵字時，該行才會被選取高亮。
- **OR 模式**：只要該行出現任何一個解析出的關鍵字，該行即會高亮。

## 4. 高效能多重高亮繪製
- 重寫了 `DrawSubItem` 邏輯，改用 `TextRenderer` (GDI) 進行更精準的文字測量。
- 能夠在同一個儲存格內，同時標註多個不同的關鍵字命中區域 (全部標註為黃底黑字)。
- 高亮邏輯會優先匹配長度較長的關鍵字，避免短關鍵字誤食長關鍵字的部分（例如同時搜尋 "app" 與 "apple"）。

## 驗證結果
- [x] 空白分隔搜尋：輸入兩個單字，功能正常。
- [x] 引號片語搜尋：帶空格的片語不被拆分，功能正常。
- [x] AND/OR 切換：切換按鈕狀態後，搜尋結果立即聯動更新，邏輯正確。
- [x] 效能：即使在大量 Debug 訊息滾動時，繪製依然流暢無閃爍。
- [x] **對齊修正**：修正了原本搜尋時會導致右對齊欄位 (時間、間隔) 跳回左對齊的問題，現在繪製邏輯會自動偵測並遵守 ListView 欄位的對齊設定 (Left/Center/Right)。
- [x] **視窗同步**：`DebugForm` 現在會完美跟隨 `Form1` 的移動與縮放，並自動將右側寬度延伸至螢幕邊緣。
- [x] **欄位自適應**：`DebugForm` 變大時，最左側的 Debug Message 欄位會自動填滿空間，右側時間欄位則保持固定並靠右對齊。
- [x] **防閃爍優化**：透過啟用 `DoubleBuffered` 以及改用 `WM_SETREDRAW` 取代舊式的 `LockWindowUpdate`，大幅減少了縮放視窗時可能出現的黑影或閃爍現象。
- [x] **變更標記**：代碼中已加入 `by AntiGravity, 2026/3/26` 註解以標記此次修改。
