# Tab 3 搜尋結算邏輯與圖表修復總結

根據您的需求，我們已經調整了 Tab 3（附件搜尋）的中斷行為，使其在按下 ESC 鍵時能「保留已搜尋成果」而非「直接丟棄」。

## 修改與成果

### 1. Tab 3 搜尋中斷保留 (及時結算)
- **商務邏輯層**: 修改了 `FilterByAttachDetailsAsync`。現在當深層過濾（Phase 2）被中斷時，它會安靜地捕捉例外，並直接回傳目前已經比對成功的郵件清單。
- **UI 事件層**: 在 `Button3_Click` 的 Phase 1 (蒐集清單) 階段加入了局部攔截。即使在蒐集郵件 ID 的過程中中斷，系統也會將目前已收集到的郵件交給後續的管線繼續執行過濾與顯示。
- **使用者體驗**: 按下 ESC 後，進度條會顯示「已結算 (中斷)」，並在 ListView3 中顯示目前蒐集到的結果。

### 2. 圖表高亮函式緊急修復 (災後重建)
- **受損修復**: 修復了因核心程式碼更動期間，工具誤將搜尋變數植入 `BrushChartHoverState` 導致的損毀。
- **現狀**: 已經過手動校對，`BrushChartHoverState` 已恢復 100% 正確的渲染邏輯，圖表選取高亮功能運作正常。
