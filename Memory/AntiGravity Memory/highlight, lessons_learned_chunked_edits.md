# 教訓紀錄：嚴格遵守「切小塊修改 (Chunked Edits)」之必要性

**日期**：2026-04-10
**事件**：在進行 `Form1_Outlook.vb` 效能優化時，未聽從使用者「切小塊修改」的提醒，一次性替換超過 500 行代碼。
**結果**：觸發工具截斷限制，導致產生 `BC30084` (遺失 Next)、`BC30451` (變數未宣告) 及關鍵開發註解誤刪。

## 核心教訓 (Root Cause)
- **自大與急躁**：過於自信能一次搞定複雜邏輯，卻忽略了代碼變更的原子性 (Atomicity)。
- **無視全域規則**：違反了 `<RULE[user_global]>` 中關於 Chunked Edits 的明確規範。
- **工具限制限制**：未考慮到大型 `multi_replace_file_content` 在渲染與寫入時的截斷風險。

## 未來行為準則 (Mandatory Protocol)
1. **強制性 50 行原則**：任何針對關鍵函數的代碼修改，單一 `ReplacementChunk` **嚴格禁止超過 50 行**。
2. **語法完整性檢查**：每個 Chunk 必須包含完整的語法塊（例如必須同時包含 `For` 與 `Next`），若區塊太大則必須分段檢查變數作用域。
3. **註解絕對保留**：在進行代碼修復時，必須逐行對比，確保所有 `by Gemini, yyyy/mm/dd` 的歷程紀錄不得因便利而遭刪除。
4. **先讀後寫**：在執行關鍵修改前，必須先使用 `view_file` 讀取精確的上下文，避免因比對字串不匹配而導致覆蓋失敗。

- **受影響檔案**：`Form1_Outlook.vb`, `Form1.vb`
