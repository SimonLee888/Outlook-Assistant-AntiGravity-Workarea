- `[x]` 修正 ListView5 郵件大小排序問題
  - 釐清 ListView5 的排序邏輯：確認其與 ListView3 相同，皆是直接依據 `MailItemInfo.Size` (Long 型別) 進行數值排序，而非字串排序，不需手動去除 "KB"。
  - 發現群組間排序時的視覺斷層問題：原本使用 `Items.First()` 取得群組內第一筆未排序的郵件大小作為該群組代表值，導致跨群組時產生大小顛倒，被誤認為字串排序。
  - 修正：將 `Items.First()` 改為依據排序方向使用 `Items.Min()` 或 `Items.Max()` 取代，使群組間的排序邏輯與群組內一致，徹底解決視覺跳躍。
