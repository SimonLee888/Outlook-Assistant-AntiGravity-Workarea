# ListView4 相似度計算效能優化紀錄

解決了在選取郵件並觸發大量相似度重算時，使用者介面（UI）會感到「被停住」的問題。

## 變更內容

### 1. 介面重繪保護 (BeginUpdate / EndUpdate)
- 在 `Lv4_SelectedIndexChanged` 事件中，針對「初始化標記計算中」與「最終填入相似度結果」這兩個會大量修改 ListView 欄位的循環，加入了 `BeginUpdate()` 與 `EndUpdate()`。
- **效益**：大幅減少 WinForms 在每個項目變動時觸發的無謂重繪，這是消除「凍結感」最有效的方法。

### 2. 優化非同步「呼吸頻率」
- **調度端控制**：在獲取郵件內容的循環中，從原本「每封信都 Await」改為「每處理 30 封信才執行一次 `Await Task.Delay(1)`」。
- **移除底層 Yield**：移除了 `GetMailBodyL3` 內部的 `Await Task.Yield()`。
- **效益**：減少了 UI 執行緒在處理大量回調任務時的調度開銷，讓 UI 執行緒有更多空檔處理滑鼠移動與介面操作訊息。

### 3. COM 存取效能優化
- 透過減少不必要的 Yield 與執行緒切換，縮短了 COM STA 執行緒的佔用時間。

## 驗證結果
- [x] **UI 響應性**：在處理 500 筆以上郵件時，介面不再發生長時間的完全鎖死現象，標記「計算中」與顯示結果的過程變得平滑。
- [x] **正確性**：相似度計算結果依然正確，"Base" 與百分比標記位置無誤。
- [x] **取消機制**：快速切換游標時，先前的計算任務能被正確取消，不會發生舊資料蓋掉新資料的問題。
