# [Walkthrough] Status Bar UI 風格標準化與對調報告

本階段我們完成了全軟體進度提示系統的高階風格統一。主要解決了 `lblStatus1` 與 `lblStatus2` 在長度與語意上的分配不對等問題。

## 1. 改進成果

根據您的建議，我們將兩者職責進行了明確定義與對調：

| 標籤 | 原始對應 (舊) | 標準化後 (新) | 特性 |
| :--- | :--- | :--- | :--- |
| **lblStatus1** | 詳細細節 (長) | **結果與計時統計 (短)** | 左右對口，讓核心數據出現在左側看板位。 |
| **lblStatus2** | 耗時統計 (短) | **處理過程詳細路徑 (長)** | 延展性佳，適合顯示長路徑而不影響統計讀取。 |

## 2. 修改範圍詳述

### 📁 分頁進度回報標準化
*   **Tab 1 (資料夾樹)**: 現在展開資料夾時，路徑明細顯示在中央，統計秒數顯示在左側。
*   **Tab 3 (附件搜尋)**: 掃描 Phase 1/2 的複雜夾名路徑全部移至右側，最終的「共找到 X 封 / 耗時 Y 秒」彙總於左側。
*   **Tab 4 & 5 (系列與重複)**: 重構完成。在掃描數千個資料夾時，左側不再會頻繁閃爍長路徑，而是穩定的顯示「正在處理...」，由右側標籤承接變動細節。

### ⚙️ 統一的操作行為
*   **ESC 中斷**: 統一由 `lblStatus1` 回報 `已中斷。`，與所有分頁行為一致。
*   **計時器清空**: 所有 Tab 按下按鈕的瞬間，都會先清空兩側狀態並重新分配職責。

---

## 3. 驗證建議

1. **視覺檢查**: 執行 Tab 5 的全信箱掃描，觀察狀態列。左側應該會穩定顯示計數，而右側會快速跳動顯示資歷夾路徑。
2. **一致性**: 隨便切換到 Tab 3 搜尋附件，確認其回報風格是否與 Tab 5 一致（不再有 1、2 職責反轉的情況）。

**本次 UI 整形已確保 Outlook Assistant 的操作體驗更加專業且穩定！**
