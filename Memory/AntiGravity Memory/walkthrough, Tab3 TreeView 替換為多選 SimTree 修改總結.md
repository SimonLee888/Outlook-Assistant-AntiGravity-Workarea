# Tab3 TreeView 替換為多選 SimTree 修改總結

我們已經將 Tab3 的搜尋邏輯與新控制項 `SimTree3` 對齊，使其完整支援多選資料夾操作。

## 變更摘要

1. **多節點選取 (`Button3_Click`)**:
   - `Button3_Click` 啟動時不再只索取 `SimTree3.SelectedNode` 單一節點。
   - 改為迭代 `SimTree3.SelectedNodes`，將觸發的所有根節點都納入搜尋範圍。

2. **跨資料夾去重 (`HashSet(Of String)`)**:
   - 如果使用者選中了「父資料夾」同時也勾選了「其子資料夾」，程式會透過 `HashSet` 以 `FolderPath` 來檢查。
   - 所有展開的子資料夾只會被加到 `folderList` 一次，不會產生重複附件與統計混亂的問題。

3. **精確的進度條母數**:
   - 根據使用者建議，匯集完 `folderList` 後，程式會向 L2.5 快取層 (`GetCachedMailCount`) 查詢這些資料夾**實際共包含幾封信**並加總為 `totalMailCount`。
   - 此總數會顯示在「準備掃描 X 個資料夾 (相依包含共計 Y 封信)...」的中繼進度上，提供更完整的資訊。

4. **相容性預留**:
   - 先前單選用的除錯或測試代碼 (如測試 DASL 按鈕) 維持使用 `SimTree3.SelectedNode`。由於這是一個安全的 Shadow API（詳見下述），因此無須改動也不會當機。

## 設計細節解說

針對您提問的兩個 SimTree 特點，在此詳細說明：

> [!NOTE] 
> **什麼是 Shadows 屬性？**
> 原本微軟標準的 `TreeView` 提供了一個 `SelectedNode` 屬性。當我們撰寫 `SimTree` 以支援多選時，必須建立自己的 `SelectedNodes` 清單 (List) 來儲存複數個被選取的項目。為了不讓原本只依賴單一選項的功能 (例如某些第三方代碼或歷史代碼) 出錯，`SimTree` 使用了 VB.NET 的 `Shadows` 關鍵字，建立了一個名為 `SelectedNode` 的新屬性，把它覆蓋掉。
> 回傳邏輯是：在多選項目中，系統只會默默記住**「您最後一次點擊的那個節點」**，並把它當作 `SelectedNode` 傳回。
> - **影響**：程式如果向它要求 `SelectedNode` 不會報錯，但如果本來是期望抓取**全部**範圍的處理，只呼叫 `SelectedNode` 會漏掉其它項。在 Tab3 我們全部改為呼叫 `SelectedNodes`。

> [!NOTE] 
> **MouseUp 事件與原生 TreeView 差異在哪？**
> 原生的 `TreeView` 是在您滑鼠按鍵**甫按下去那一刻 (MouseDown)** 即觸發 `AfterSelect` 選取完成事件。
> 而 `SimTree` 因為需要支援按住 **Shift（區間選擇）** 或 **Ctrl（加總選擇）** 的判斷動作，它會將主要判斷和觸發延後到您手指**放開滑鼠的那一刻 (MouseUp)** 才觸發選取並發射 `AfterSelect`。
> - **影響**：純粹就只有那一丁點按住與放開的「時間差」。由於 Tab3 是選好後**按另一個獨立按鈕 `Button3` 才發動搜尋**，這個時間差不會有任何實質影響。

## 驗證項目
您可以實際開啟程式嘗試以下操作：
1. **複選搜尋**: 同時選中多個含附件的不同郵件資料夾，按下搜尋確認結果都能包含並被過濾。
2. **跨層級去重**: 刻意選取有包含關係的父子資料夾（並勾選搜尋子資料夾），檢查搜尋的附件檔是否不會出現雙胞胎的重疊結果。
3. **取消檢查**: 在啟動大範圍的複選後，嘗試點選原本設計的停止按鈕 (ESC)，確認多重迴圈是否能順利中斷。
