## 全域架構原則（已確認，勿再修改）

### COM / 執行緒規則
- 所有 Outlook COM 呼叫必須在 UI 執行緒（STA）
- 不可用 Task.Run / Parallel.ForEach 包住 COM 物件（Tab1/Tab2 例外：L3 用 Parallel.ForEach 但保留，效能實測更快）
- 用 `Await Task.Yield()` 讓 UI 不凍結，不切換執行緒
- `Task.WhenAll` 只有跨 PST 才真正有效（同一 PST 是單一檔案，並行讀取鎖競爭反而慢）

### Cache 設計（已決定，不改）
```vb
' key = Outlook.Folder COM 物件（接受偶爾 RCW 不同的 cache miss）
Private Shared ReadOnly mailCountCache As New ConcurrentDictionary(Of Outlook.Folder, Integer)
Private Shared ReadOnly folderCountCache As New ConcurrentDictionary(Of Outlook.Folder, Integer)
Private Shared ReadOnly folderSizeCache As New ConcurrentDictionary(Of Outlook.Folder, Long)
Private Shared ReadOnly folderTreeCache As New ConcurrentDictionary(Of Outlook.Folder, List(Of Outlook.Folder))
' key = FolderPath 字串（Tab2 快取，穩定不受 RCW 影響）
Private Shared ReadOnly yearCountsCache As New ConcurrentDictionary(Of String, ConcurrentDictionary(Of Integer, Integer))
Private Shared ReadOnly monthCountsCache As New ConcurrentDictionary(Of String, ConcurrentDictionary(Of Integer, Integer))
```

## Tab1 資料夾統計（已完成重構 v4）

### 分層架構
```
L1  TreeView1_AfterSelect     UI 事件層：序號防護 + 呼叫 L2 + 批次寫 ListView
L2  ComputeFolderStatsAsync   流程協調層：BFS 展開 + 快取剪枝 + 底部向上彙總
L3  GetDirectMailCountL3      COM 資料層：只讀 PR_CONTENT_COUNT，不遞迴
```

### 已修正的關鍵 Bug
1. **root 快取命中時不展開子資料夾（v1 bug）**：BFS 剪枝改成 `If curr.parentIdx <> -1 Then Continue Do`，root（parentIdx=-1）永遠展開直屬子資料夾
2. **第二次點選數字累加**：Step3 底部向上彙總加 guard：`If Not parent.IsFromCache Then` 才累加，否則快取命中的 parent 已含子孫總計，再疊加會雙重計算
3. **GetFolderSizeLINQ 移除 Task.Run 包 COM**：改用 GetTable + PR_MESSAGE_SIZE 在 UI 執行緒循序讀取，每 Row 釋放 RCW，每 500 筆 Yield 一次

### PST Folder Size 屬性研究結論
- `PR_MESSAGE_SIZE_EXTENDED (0x0E080014)` 和 `PR_MESSAGE_SIZE (0x0E080003)` 在本地 PST 均回「未知或找不到」
- MS-PST 官方規格確認：PST folder object 根本沒有儲存彙總 size 屬性
- Exchange server 有實作，PST store provider（pstprx.dll）沒有實作
- **GetTable 遍歷是 PST 上唯一可靠方案**，沒有更快捷徑

### 效能數據（實測）
| 版本 | 第一次讀取 | 快取命中 |
|---|---|---|
| 原始版 | 基準 | 0.10~0.19s |
| v2 Task.WhenAll | 明顯快 | 0.04~0.09s |
| v4 BFS sequential | 最快 | **0.01s** |

v4 快取 0.01s 的原因：命中時完全不碰 thread pool，BFS 直接讀記憶體快取值 → 底部向上加總 → 結束

## 背景預熱系統（已設計完成，待導入 Form1）

### 設計檔案：Tab_Prewarm.vb

### 50% 時間限制方式
```
[工作 X ms] → [Task.Delay(X ms)] → [工作 X ms] → [Task.Delay(X ms)] ...
```
用 Stopwatch 量實際工作時間，再 Task.Delay 等相同時間，自動適應不同硬碟速度。

### 預讀順序與策略
1. **PrewarmTab1Async**：跨 PST Task.WhenAll 並行，GetMailCountByMAPINew + GetTotalFolderCountAsync
2. **PrewarmTab2Async**：跨 PST Task.WhenAll，同 PST 內逐資料夾 sequential，每個資料夾各自計 50% 延遲
3. **PrewarmTab3Async**：同上，ScanFolderWithGetTable 用 hasattachment 基礎 filter

### 需要加入 Form1 的三處
```vb
' 成員變數
Private _prewarmCts As New CancellationTokenSource

' Form1_Load 末尾
PrewarmAllCachesAsync(_prewarmCts.Token)   ' fire-and-forget

' Form1_FormClosing
_prewarmCts.Cancel()
```
