### 4. ESC 中斷機制（2026/04/15 完成全面 cToken 化）

**架構**：`Form1_KeyDown → _cts.Cancel() → cToken 失效`

```vb
' Form1.vb 成員變數：
Private _cancelRequested As Boolean = False   ' 舊旗標，仍保留供部分尚未換完的地方
Private _cts As CancellationTokenSource

' OkayNowYouHaveToken()：取得新 Token，同時取消上一次操作
Private Function OkayNowYouHaveToken() As CancellationToken
    If _cts IsNot Nothing Then Try : _cts.Cancel() : _cts.Dispose() : Catch : End Try
    _cancelRequested = False   ' 重置舊旗標（保險用）
    _cts = New CancellationTokenSource()
    Return _cts.Token
End Function
```

**ThrottledYieldAsync helper**（已加入 `Form1_Outlook.vb` ■輔助函數 Region）：
```vb
' 2026/04/15 by Claude: 統一節流讓出點，取代各處散落的 swThrottle + Task.Delay(1) 組合
' 熱路徑（sw < intervalMs）：直接回 Task.CompletedTask，零分配
' 冷路徑（sw >= intervalMs）：sw.Restart() → Task.Delay(1, cToken)
'   Task.Delay(1) 在 Windows 預設計時器下實際等 ~15.6ms，
'   但每 100ms 才觸發一次，整體開銷比 < 16%，15.6ms 足夠讓消息泵處理 ESC。
'   不使用 Application.DoEvents()（Async 函數中有再入風險）
'   不使用 timeBeginPeriod(1)（Windows 10 是全域設定，桌機額外耗電 13~25W）
Private Function ThrottledYieldAsync(sw As Stopwatch, cToken As CancellationToken,
                                     Optional intervalMs As Integer = 100) As Task
    If sw.ElapsedMilliseconds < intervalMs Then Return Task.CompletedTask
    sw.Restart()
    Return Task.Delay(1, cToken)
End Function
```

**OCE 處理原則（2026/04/15 確定）**：

| 函數 | OCE 處理 | 理由 |
|---|---|---|
| `GetMailCountAll` ①② | `Catch OCE → Return -1` | -1 = 取消/失敗，L2.5 檢查 IsCancellationRequested 不寫快取 |
| `GetFolderCountAll` ⓪② | 同上 | 同上 |
| `GetFolderSizeAll` ⓪① | 同上 | 同上 |
| `GetFolderSize` ①② | **`Catch OCE → Throw`** | re-throw 讓 GetFolderSizeAll ① 的 For 迴圈感知 |
| `GetYearCountsForFolder` | **`Catch OCE → Throw`** | 攔住會回傳半截 yearCounts，L2 誤存不完整快取 |
| `GetMonthCountsForYear` | **`Catch OCE → Throw`** | 同上；_cacheMonthCounts 寫入在 Loop 後，OCE 天然走不到 |
| `GetAttachMailList` | `Catch OCE → Return Empty List` | 半截清單不可信；呼叫端 GetCachedAttachMailList 取消時不寫快取 |

**Parallel.ForEach 的取消方式**：一律改用 `ParallelOptions.CancellationToken = cToken`，不再用 `If _cancelRequested Then Return` 在 lambda 內部檢查。取消時 `Parallel.ForEach` 拋 `OperationCanceledException`（含於 `AggregateException`），由外層 `Catch ex As OperationCanceledException` 接住。

## 全域架構原則

### COM / 執行緒規則
- 所有 Outlook COM 呼叫必須在 UI 執行緒（STA）
- 不可用 Task.Run 包住 COM 物件
- Redemption 是 free-threaded，可在 Task.Run / Parallel.ForEach 中呼叫
- 讓出 UI 執行緒：`Await ThrottledYieldAsync(sw, cToken)` 每 100ms 一次（取代 Task.Yield / Task.Delay(1) 無 token）
- ESC 中斷：`_cts.Cancel()` → cToken 失效 → ThrottledYieldAsync 拋 OCE 或 Parallel.ForEach 拋 OCE

### Outlook Namespace 衝突
- `System.Exception` 必須寫全名
- `System.Windows.Forms.View.Details` 不可縮寫
- ListView `View` 屬性等衝突名稱都要加全名前綴

### L3 函數設計原則
- Fallback 鏈：⓪ Redemption → ① MAPI PropertyAccessor → ② OOM → ③ return -1
- 失敗統一回傳 -1（不回 0），讓 L2 能區分「真的是 0」或「讀取失敗」
- Finally 中統一釋放 COM 物件（`TryMarshalRelease()`）
- Catch 必須先攔 `OperationCanceledException` 再攔 `System.Exception`，否則 OCE 會被 System.Exception 吞掉

## 已確認的死路（PST 限制，勿再嘗試）

- DASL/Restrict 無法篩附件檔名（PST 無索引）
- `AdvancedSearch` 在 LTSC 失敗（HResult=0x8007064F）
- `SetColumns` 加 `PR_ATTACH_LONG_FILENAME` → NullReference（附件是子物件，非 MailItem 頂層屬性）
- `PR_MESSAGE_SIZE_EXTENDED (0x0E080014)` 和 `PR_MESSAGE_SIZE (0x0E080003)` 在 PST folder object 均回「未知或找不到」
- `GetTable + GetArray()` 無法取附件檔名
- `Application.DoEvents()` 在 Async 函數中有再入風險（堆疊深度持續增長）
- `timeBeginPeriod(1)`：Windows 10 是全域設定，桌機額外耗電 13~25W，不值得
