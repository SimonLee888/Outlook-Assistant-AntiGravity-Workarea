## 專案背景（快速摘要）

VB.NET (.NET 10) WinForms，分析本機 Outlook PST 存檔（5~25 個 PST，最多 35 萬封郵件）。  
Outlook LTSC 2021 COM 互通 (olNotExchange/PST)，可選 Redemption RDO 加速。

**Partial class 分檔**

- `Form1.vb`（■01–■10 Regions）— 主 UI 事件 + 共用工具
- `Form1_MainTabs.vb` — Tab1 BFS + Tab2 日期統計 + Tab3 附件搜尋
- `Form1_Outlook.vb` — Outlook COM 存取 + 所有 `_cacheXxx` Shared 欄位
- `Form1_SQLite2.vb` — SQLite 快取層（OLAcache.db）
- `Form1_OST.vb` — Tab7 OST/PST 解析（本次新增）
- `Form1_DebugForm.vb`、`Form1_SimTree.vb`、`Form1_Win32API.vb`、`Form1_Designer.vb`
- C# ost2pst library（獨立專案，編譯成 DLL）：`FileManager.cs`、`XstFile.cs`、`LTP.vb`、`NDB.vb` 等

**架構層次**：L1 UI → L2 BFS 流程協調 → L2.5 快取代理（Memory→SQLite→COM）→ L3 單責 COM 存取

### ✅ 任務 2：C# ost2pst library 解耦（FM.StatusMsg）

**問題**：library 直接呼叫 `Program.mainForm.statusMSG(x)` → UI 依賴，無法從 VB 端控制。

**解法**：在 `FM` static class 加入 delegate：

```csharp
public static Action<string> StatusMsg = _ => { };
```

VB 端在使用前設定：

```vb
FM.StatusMsg = Sub(msg) Me.BeginInvoke(Sub() lblStatus.Text = msg)
```

Finally 清除：`FM.StatusMsg = Sub(msg) _ = msg`

**修改處**：`FileManager.cs`（9 處） + `XstFile.cs`（2 處）→ 全部 `Program.mainForm.statusMSG(x)` → `FM.StatusMsg(x)`

**FM 公開介面（VB 端使用）**：

```
ost2pst.FM.StatusMsg            — Action(Of String) delegate
ost2pst.FM.OpenSourceFile(path) — Boolean
ost2pst.FM.GetFolderList()      — 結果存 FM.folders
ost2pst.FM.folders              — List(Of ost2pst.Folder)
ost2pst.FM.CloseSourceFile()
```

`ost2pst.Folder` 欄位：`.name` / `.path` / `.parent`（物件參考，根節點自指）/ `.level` / `.nbtIndex` / `.nid`

## 關鍵架構原則（累積）

**PST 環境確認死路**：

- `PR_MESSAGE_SIZE_EXTENDED (0x0E080014)` / `PR_MESSAGE_SIZE (0x0E080003)` 在 Folder 物件上回傳 unknown
- DASL/Restrict 無法過濾附件檔名屬性（attachments 是 sub-object）
- `AdvancedSearch` → `HResult=0x8007064F`（Windows Search 未啟用）
- `PR_ATTACH_LONG_FILENAME` 從 `GetTable` message row 讀取為 null
- `Items.SetColumns()` 導致 `mail.Attachments` 為 null

**COM / 執行緒原則**：

- COM 呼叫必須留在 UI 執行緒（STA）；用 `Await Task.Yield()` 保持 UI 回應，不用 `Task.Run`
- `Task.Yield()` 成本 5–15ms；快速 COM 操作每 10 次 yield 一次
- 快取 key 用 `folder.FolderPath` 字串，不用 COM Folder 物件（防 RCW 滯留）

**常見陷阱**：

- `TryGetValue` miss 回傳 default Integer `0`；SQLite 未測量欄位需存 `DBNull.Value`（非 0/-1），讀取時用 `IsDBNull`
- `SelectedItems.Clear()` 拋 `NotSupportedException`；需逐項 `Selected = False`
- `Shadows` 屬性非多型（dispatch 依編譯時型別）
- `If intValue Mod N Then` 語意相反，需 `If intValue Mod N = 0 Then`
- `DROP TABLE IF EXISTS` 在 `GetCreateTablesSql()`（每次啟動）會清資料；schema 遷移應在 `InitDatabase()` 以 `PRAGMA table_info` 一次性處理
- `Microsoft.Data.Sqlite`：`SqliteType.Integer` 欄位不可設 `DBNull.Value`，應省略該欄位讓 SQL 得到 NULL

**Redemption**：

- `TotalItemCount` / `FolderSize` 一次 COM call 回傳遞迴子樹總計，消除 BFS 需求
- 多個 `RDOSession` 並行在單一 PST 上超過 2–4 thread 後回報遞減（內部鎖競爭）

**程式碼風格**：

- 壓縮 VB.NET 語法；中文行內注解含設計理由與日期
- `System.Exception` 全名限定（避免 Outlook 命名空間衝突）
- `_dbg()` / `Dbg()` wrapper（`<Conditional("DEBUG")>` 屬性）為主要除錯工具
- 所有既有 `_dbg()` 呼叫與注解需完整保留，不得省略
