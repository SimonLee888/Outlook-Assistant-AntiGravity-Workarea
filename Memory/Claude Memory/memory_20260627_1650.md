## 1. 專案脈絡

VB.NET (.NET 10 WinForms) 應用，處理大型本機 Outlook PST 封存（~350,000 封 / ~27 個 PST）。
技術棧：Outlook LTSC 2021 OOM (OOM interop) + Redemption RDO 6.7 + SQLite (Microsoft.Data.Sqlite)。
分層架構：**L1 UI → L2 邏輯 → L2.5 快取代理(dispatcher) → L3 底層 COM 讀取**。
資料庫：`OLAcache.db`（夾統計/郵件 metadata）、`OLAcacheMail.db`（attach_filenames + mail_simhash，survives cache 重建）。

## 2. ★ L3 讀取函數三分命名結構（2026/06/27 大改名後）

這兩天把所有「已切出 RDO 段落」的讀取群統一成三分結構，命名語意化、好辨識：

### (a) L2.5 Proxy（快取代理/分派器，**不放邏輯**）
讀取順序：`① 記憶體快取 → ② DB lazy load → ③ 派工(RDO 優先,失敗 fallback OOM)`
- `GetMailCount` (skipCache)
- `GetFolderCount` (skipCache)
- `GetFolderSize` (skipCache) — 2026/06/27 補上 `_rdo2` size 槽
- `GetFolderSizeAll` (建議補 skipCache，理由見 §3)
- `GetAttachFilename` (skipCache)
- `GetMailBody` (skipCache)
- `GetSubtreeToList` (skipCache)
- `GetMailCountAllAsync` / `GetFolderCountAllAsync` — **死碼**（無呼叫端）。真正的 count-all 走 Tab1 BFS：`Compute → BFS → SummarizeSubTreeBottomUp → 直接寫 _cacheXxxCountAll`，繞過這兩個 proxy。

### (b) `*Rdo`（Layer3 RDO 加速讀取層，跑 `_rdo2` 獨立 session，store-scoped）
解析失敗回 `-1`（數值類）或 `Nothing`（清單/字串類），由 proxy 判 `<0`/`Nothing` fallback 到 OOM。
- `GetMailCountRdo` / `GetFolderCountRdo` — `rdoFolder.Items.Count` / `.Folders.Count`（便宜快取屬性）
- `GetFolderSizeRdo` — `RDOItems.MAPITable` 批次 `GetRows` 加總（詳見 §3）
- `GetAttachFilenameRdo` / `GetMailBodyRdo`
- `GetSubtreeRdo`（派工殼）→ `GetSubtreeRdoBatch`（`Folders.MAPITable` 批次,135×）/ `GetSubtreeRdoEnum`（枚舉 fallback）

### (c) `*OOM`（Layer3 OOM 直接存取，fallback / 新鮮 COM 讀取）
- `GetMailCountOOM` / `GetFolderCountOOM` / `GetMailCountAllOOM` / `GetFolderCountAllOOM`
- `GetFolderSizeOOM` / `GetFolderSizeAllOOM`
- `GetAttachFilenameOOM` / `GetMailBodyOOM` / `GetSubtreeOOM`

> 分派合約：`proxy →（skipCache 則跳過 ①②）→ Rdo（_rdo2 在且 store 解得到）→ 回 <0/Nothing → OOM`。
> 插 `_rdo2` tier 進 L2.5 後，Tab3/4/5 多數呼叫端零修改——分層界線乾淨的回報。

## 3. ★ 資料夾大小讀取（GetFolderSizeRdo）— 探針實證結論

- **必用 `PR_MESSAGE_SIZE`（PT_LONG, 0x0E080003）逐封 GetRows 加總**，VB 端累進 `Long`(64-bit)。
  - 單封 size < 2GB，PT_LONG 必夠；總和進 64-bit 不溢位（實證 2009 夾 6.4GB 總和正確）。
  - 速度比 OOM `GetTable+GetArray` 快 **3~10×**，parity 全一致。
- **絕不可用 `PR_MESSAGE_SIZE_EXTENDED`（PT_I8, 0x0E080014）走 GetRows**：每封回相同垃圾常數 ≈ −2³¹（8-byte marshaling 壞）。OOM GetArray 讀 PT_I8 是好的（基準），但 RDO GetRows 讀 PT_I8 壞。
- **讀取成本 ∝ 封數（row count），非 size**：GetTable/GetRows 一列一封讀固定寬度屬性，信的 bytes 與成本無關。封數與 size 在信箱裡共線，故「看起來也跟 size 相關」；每封邊際 ~0.004 ms/封。優化時用封數思考，不是 GB。

**GetFolderSizeAll 加 skipCache（待補）**：Tab12 F5「強制更新」現在只 `_cacheFolderSizeAll.TryRemove`（清記憶體），② DB lazy 仍會回 DB 的 fsa → 非真正強制。加 skipCache 跳過 ①② 才保證重算。caveat：只強制子樹層 fsa；內部逐夾 `GetFolderSize` 的 per-folder fs 不會自動 skipCache（暫不往下傳遞）。

## 4. skipCache 合約

proxy 上的 `Optional skipCache As Boolean = False`：
- `True` → 跳過 ① 記憶體 + ② DB lazy，直接走 ③ 派工（RDO→OOM）；**且不寫快取**（`If Not skipCache Then ...`）。
- 用途：F5 強制更新、SQLite snapshot 不一致重讀等「繞過 proxy 直呼 L3 強制讀 COM」的呼叫端，改走單一入口仍享 RDO 派工。
- 已套：`GetMailCount` / `GetFolderCount` / `GetFolderSize` / `GetAttachFilename` / `GetMailBody` / `GetSubtreeToList`。
- 直呼端改走 proxy 範例：`Module_SQLite2` 狀況 A snap 重讀 `_cacheXxx(fPath) = GetXxx(folder, fPath, skipCache:=True)`。

## 5. RDO Session 模型

- `_rdo`：piggyback 在 `_olNS.MAPIOBJECT`（共用 Outlook MAPI session）。**慢**，效能上不來。
- `_rdo2`：獨立 `RDOSession`（`Logon` 開新 session）。對子樹走訪快 ~135×、開信/讀附件/讀內文快 ~10×。**session 獨立才是效能槓桿，不是平行。**
- 兩者在 `InitRdoSessionWithoutEULA` **同生**、`ReleaseRdoSession` **同滅**（invariant：兩者恆同時 Nothing 或同時在），CheckRDO 勾選控制。
- `GetRdoStore(folderPath)`：回 `_rdo2` 上記憶化快取的 RDOStore，**不可釋放**；內部用一般 `Dictionary`（**UI 緒專用**，背景緒呼叫會 race → 須在 UI 緒先解好 store 再帶進 Task.Run）。
- store-scoped 解析：`store.GetFolderFromID(eid)`（單參數，OOM EntryID 與 RDO-table hex eid 皆可解）。

## 8. 關鍵原則與教訓

- **架構**：每次修改維持「一致、對稱、解耦、介面清楚乾淨抽象、呼叫路徑統一」。L2.5 是 dispatcher 不是邏輯歸宿；RDO 讀取函數歸 Layer3 RDO 區。
- **PST size**：PST folder object 無彙總 size 屬性（`PR_MESSAGE_SIZE_EXTENDED`/`PR_MESSAGE_SIZE` 在 folder 層回「unknown」）；唯一可靠是逐封加總。
- **RDO 批次**：`MAPITable.GetRows(n)` = OOM `GetArray` 對等物（不是 `GetArray`）；`Columns` 是可寫屬性（非 collection、無 `.Clear`）；`ExecSQL` 支援 `COUNT(*)/WHERE/TOP/LIKE/IN`，不支援 `JOIN/GROUP BY`、`SUM(size)` 會 crash。
- **COM**：所有 OOM 呼叫須在 UI/STA 緒；`Task.Run` 不可包 OOM COM（RDO free-threaded 例外）。`System.Exception` 須完全限定（Outlook 命名衝突）。`TryMarshalRelease` 清理。
- **除錯紀律**：probe-then-commit；grep 呼叫端一輪到位（Region/死活/語意全歸類）；`#Region "■ 99 舊版備用 (勿刪)"` 永久禁區、grep 命中視死路徑略過。
- **OOM `.Body` 讀 IRM 信會觸發隱藏授權 modal → UI 緒死鎖**；IRM 操作全程走 RDO 規避。
