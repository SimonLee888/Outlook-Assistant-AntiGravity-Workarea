## 全域架構原則（已確認，勿再修改）

### COM / 執行緒規則
- 所有 Outlook COM 呼叫必須在 UI 執行緒（STA）
- 不可用 Task.Run 包住 Outlook COM 物件（Redemption RDO 物件是 free-threaded，可以）
- 用 `Await Task.Yield()` 讓 UI 不凍結，不切換執行緒
- `Task.WhenAll` 只有跨 PST 才真正有效（同一 PST 鎖競爭反而慢）
- **重要**：所有 Catch 要寫 `System.Exception`（因 Imports Outlook 導致命名空間衝突）

### Outlook Namespace 衝突
- `Imports Microsoft.Office.Interop.Outlook` 會讓 `View`、`Exception` 等名稱衝突
- ListView 的 `View` 屬性必須寫完整名稱：`System.Windows.Forms.View.Details`
- Catch 必須寫 `System.Exception` 而非 `Exception`

### 全域物件命名（重要，勿混淆）
```vb
Private _olApp As Outlook.Application       ' Outlook Application
Private _olNS As Outlook.NameSpace          ' Outlook MAPI NameSpace
Private _rdo As Redemption.RDOSession       ' Redemption session（attach 到現有 _olNS）
Private _pstStoreList As List(Of ...)       ' 所有 PST store 清單
```

### Cache 設計（已確定，不改）

## Redemption 整合（2026-03-23 新增）

### 設計目標
- 繞過 Outlook Security Guard（PST 無安全性問題但仍有保護）
- RDO 物件 free-threaded，可在 Task.Run 內安全呼叫
- `TotalItemCount` / `FolderSize` 一次取得整棵子樹數值，完全不需 BFS

### 初始化流程
```vb
' Form1_Load 內 fire-and-forget（與 LoadStoreToTreeView 平行執行）
Dim unused = InitRedemptionSessionWithoutDeclaration()
```

```vb
Private Async Function InitRedemptionSessionWithoutDeclaration() As Task
    ' AutoDismiss thread 先就緒，再 Task.Run New RDOSession()
    ' Task.Run 保留：讓 UI 執行緒繼續跑 LoadStoreToTreeView（平行初始化）
    Dim threadStarted As New ManualResetEventSlim(False)
    AutoDismissRedemptionDialog(threadStarted)
    threadStarted.Wait(500)
    Dim session As Redemption.RDOSession = Nothing
    Await Task.Run(Sub() session = New Redemption.RDOSession())
    session.MAPIOBJECT = _olNS.MAPIOBJECT   ' 必須在 UI 執行緒賦值（STA）
    _rdo = session
End Function
```

### AutoDismissRedemptionDialog（v4，2026-03-23）
- WinSpy++ 確認：視窗 class = `TEULAForm`，"I agree" = `TRadioButton`，"Ok" = `TButton`
- 獨立 `New Thread()`（不用 Task.Run，避免 thread pool 競爭）
- `Thread.Priority = AboveNormal`，`IsBackground = True`
- `threadStarted.Set()` 後 `Thread.Sleep(1)` 確保輪詢 loop 真正開始再通知
- 找到視窗立刻 `ShowWindow(SW_HIDE)`，使用者看不到 EULA 閃出
- 用 `PostMessage`（非同步）而非 `SendMessage`（同步，會死結）
- 輪詢間隔 5ms，子控制項也輪詢等（不固定 Sleep）

### Win32 API 區（已整理，統一 DllImport）
```vb
#Region "■ Win32 API"
    ' FindWindow / FindWindowEx / SendMessage / PostMessage
    ' SetWindowPos / RedrawWindow / LockWindowUpdate / ShowWindow
    ' 常數：WM_COMMAND / WM_LBUTTONDOWN / WM_LBUTTONUP / BM_CLICK / SW_HIDE
    '       TV_FIRST / TVM_SETEXTENDEDSTYLE / TVS_EX_DOUBLEBUFFER
```

- Redemption 初始化與 TreeView 載入平行進行，啟動約 1.1~1.3 秒
- 原始未整合 Redemption 時約 0.5~0.6 秒，差距是 Redemption DLL 載入本身的固定開銷

## L3 底層函數群（Form1_DataLayer.vb，2026-03-23 完成）

### Fallback 鏈統一格式
所有 L3 函數都採用 ⓪→①→②→③ fallback 鏈：
- **⓪ Redemption**：最快，free-threaded，`_rdo` 未就緒時自動跳過
- **① MAPI / GetTable**：次快
- **② OOM（Items/Folders）**：保險
- **③ Return -1**：全部失敗，由 L2 決定如何處理

### GetMailCount(folder) → Integer
```
⓪ RDOFolder.Items.Count
① PR_CONTENT_COUNT (0x36020003) PropertyAccessor
② folder.Items.Count + ReleaseComObject
③ Return -1
```

### GetFolderCount(folder) → Integer
```
⓪ RDOFolder.Folders.Count
① PR_FOLDER_CHILD_COUNT (0x66380003)【已 comment 出，PST 上從未成功】
② folder.Folders.Count
③ Return -1
```

### GetMailCountAll(rootFolder) → Task(Of Long)  [v3.0，已合併平行版]
```
⓪ rdoFolder.TotalItemCount  ← 一次 call，整棵子樹，完全不需 BFS
① Task.WhenAll 平行 BFS（GetMailCount L3 逐一）
② BFS 循序累加（支援取消 + onProgress callback）
③ 遞迴 fallback
④ Return -1
```
- 原 `GetMailCountAllParallel` 已合併進來，可廢棄

### GetMailSize(item As Object) → Long
```
⓪ RDOMail.Size
① PR_MESSAGE_SIZE_EXTENDED (0x0E080014, 64-bit)
② PR_MESSAGE_SIZE (0x0E080003, 32-bit)
③ mail.Size (OOM)
```
- 接受 Object 參數，非 MailItem 直接回 0

### GetFolderSize(folder) → Task(Of Long)
```
⓪ RDOFolder.Items 迭代 + RDOMail.Size（本層 only，FolderSize 含子樹不適用）
① GetTable + PR_MESSAGE_SIZE_EXTENDED，每 500 筆 Yield
② Items.GetFirst/GetNext + GetMailSize，每 200 筆 Yield
③ Return -1
```

### GetFolderSizeAll(rootFolder) → Task(Of Long)  [v1.0，2026-03-23 新增]
```
⓪ rdoFolder.FolderSize  ← 整棵子樹大小，PST 上 OOM 無法取得，Redemption 可正確讀取
① Task.WhenAll（GetFolderSize 逐資料夾，直接 Select 不包 Task.Run）
② BFS 循序累加
③ 遞迴 fallback
④ Return -1
```

### GetFolderCount / GetFolderCountAll
```
GetFolderCount：⓪ RDO / ② OOM Folders.Count
GetFolderCountAll：① BFS .Count-1 / ② Parallel.ForEach 遞迴
（Redemption 無遞迴總數 API，FolderSize 有但 FolderCount 沒有）
```

### PST Folder Size 研究結論（更新）
- 原生 OOM：`PR_MESSAGE_SIZE_EXTENDED` / `PR_MESSAGE_SIZE` 在 PST Folder 物件上回「未知」
- 原因：Exchange 有實作彙總屬性，pstprx.dll 沒有
- **Redemption `rdoFolder.FolderSize`**：走 MAPI 底層，可正確讀取 PST 上的整棵子樹大小
- GetTable 逐封加總仍保留作 fallback
